# 超级论文阅读

让缺少领域基础的读者沿同一条逻辑线理解：问题怎样出现，本文怎样处理输入并得到结果，实验怎样检验它。默认中文连续长文；用户指定局部修订时只处理相应范围。

## 执行流程

1. 确认材料与版本。接受 PDF、论文链接、粘贴材料或已有笔记，核实标题、版本、实际主章节和可读范围。优先用户给定版本，不静默替换；材料不全时缩小解读范围。
2. 按 [证据规范](references/evidence-guide.md) 通读正文与必要附录，提取文字并查看实际图表像素；记录重要结论、条件、数字、原术语与符号的依据。必要时发现宿主运行时或查一手材料，不默认扩成综述。
3. 写作前读 [讲解规范](references/teaching-guide.md)，先用普通中文在内部串起“为什么需要下一步”的因果链，再对齐原算法、术语、公式与实验依据。首次使用或校准风格时读 [风格校准说明](references/pi0-calibration.md)；说明只提供讲法，不提供事实。
4. 按 [HTML 工作流](references/html-workflow.md) 保存 Markdown、相对路径图片，运行内置渲染器。需要 Node.js 20+，不依赖其他讲解或 HTML 技能。
5. 对照底稿验收内容，再检查成品目录、图表、公式、教学图、桌面和窄屏效果。缺少材料或未完成视觉检查时如实说明。

## 讲解主线

- Abstract 完整忠实翻译。Introduction 用五步串起故事并归并三点有据贡献。Related Work 结合全文解释问题演进、必要概念及本文位置。
- Method 只设“1. 方法概述”和“2. 具体实现”两个小标题。概述融合问题建模、原方法主图与教学示意图；实现沿原算法与计算依赖连续展开，用段落承接输入、处理、输出和下一步的必要性。沿用原阶段名、组件名与符号，不再设阶段标题、2.1等子标题或加粗的变相标题。
- Experiments 先总说待回答的问题，各组以问题为标题，结合原图表回答目的、对照、设计、具体实施、结果及原因。以原文为主，分清作者解释与额外推断，不补造缺项。

## 表达与范围

先讲当前困难和需要的能力，再引入原术语；先让读者知道要算什么及为何要算，再给原公式。普通叙述用自然中文，专有名词与符号保留原样，不把动作、观测、奖励等普通表述机械换成英文。可用同一教学例子串联各阶段，配置细节不打断机制解释。

核心机制、公式和实验充分展开，不设机械字数或图表上限。主章节保留原顺序与编号，方法章称带原编号的 Method，其内部仅保留上述两个小标题；其他章节的小节从1连续编号，每章重置，必要细分用1.1、1.2。

正文、列表与图注不加粗，数学保留原字形。不设阅读路线、“补充”类栏目、Method 教学折叠或来源核对栏目。章节／页码定位只留内部记录或隐藏注释，原图表及公式编号可保留。原文事实、外部材料、教学例子与讲解者分析须分清。

## 生成与交付

默认保存 `outputs/<paper-slug>/<paper-slug>.md`、同名 `.html` 与 `assets/`。HTML为单栏浅色长文，含目录、原图与教学示意，图片和数学资源内嵌，可离线阅读，不显示自动字母章标。

渲染：`node "<skill-dir>/scripts/render.mjs" "<draft.md>"`，自定义输出加 `--out "<page.html>"`。修改底稿后重新生成，保留底稿和资产；不修改全局设置，不自动部署、上传或启动长期服务。交付 HTML、Markdown 链接与实际材料限制。

维护和交付按 [验收场景](references/acceptance-cases.md) 检查；结构校验不能代替讲解质量与视觉验收。渲染依赖和许可证见 [第三方说明](licenses/NOTICE.md)。
