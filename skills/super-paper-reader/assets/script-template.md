# ⟨中文标题⟩（⟨English Original Title⟩）

> 讲解稿 · ⟨机构/团队⟩ · ⟨会议，或 arXiv 预印本 id + 日期；论文未标注会议时不得写会议⟩ · 全文 ⟨N⟩ 页
> 一句话核心：⟨机制 + 收益，一句话，要具体到做了什么、带来了什么⟩

## ⟨第一个章节标题，逐字照抄⟩

⟨**定位句**：本期/这次我要详细讲解的是…，一句话说清论文身份与地位。⟩

⟨**贡献句**：论文提出的 ⟨方法⟩ 首次实现了 ⟨能力⟩，从而 ⟨后果⟩。⟩

⟨（可选）**痛点预告**：然而通往这一目标的路上始终存在 N 个障碍。⟩

---

## ⟨Introduction 的原标题⟩

⟨**愿景 → 然而 → 根本矛盾**：先说领域愿景，紧接着转折，一句话点名矛盾的来源。⟩

⟨**矛盾的展开**：分两三层说清为什么旧范式不行（数据层 / 表征层 / 规模层）。⟩

⟨**旧方法为什么不行**：点名论文提到的具体旧方法，并给一个能记住的框架（如"大脑与身体分开了"）。⟩

⟨**本文的路子**：一句话方案 → 拆解新概念的每个词 → 说清它妙在哪。⟩

⟨**走一遍具体例子**：用论文图 1 或图 2 把输入 → 输出讲一遍。⟩

⟨**预告**：数据来源有哪几类、训练分几个阶段、后文怎么安排。⟩

⟨**承上启下**：了解了这些，我们再来看论文的相关工作。⟩

---

## ⟨Related Work 的原标题⟩

⟨**引子句**：在详细讲解 ⟨模型⟩ 之前，我们先来回顾几个相关技术。⟩

⟨对每条脉络重复以下五步：⟩

1. ⟨**脉络的定义与分叉**⟩
2. ⟨**代表工作怎么工作**：定义 → 为什么需要 → 怎么运作 → 解决什么，配一个具体例子⟩
3. ⟨**代表工作的局限**：必须有这一步⟩
4. ⟨**本文站在哪里**⟩
5. ⟨**回扣**：本文与前人的区别是什么⟩

⟨**收束句**：好，那了解完这些背景之后，我们开始进入论文的核心部分。⟩

## ⟨Method / Model 的原标题⟩

⟨**总览句**：论文第 X 节的 ⟨节名⟩ 主要围绕论文第 Y 页的图 Z 展开，是 ⟨模型⟩ 的总览。⟩

⟨**读图**：按你明确说出的空间顺序（上半/下半，或左/中/右，或从输入到输出）逐块讲。⟩

⟨**宏观架构**：由几大核心模块组成，每个模块一句话职责（收到什么、产出什么、负责什么）。⟩

⟨**两大阶段**：预训练 / 后训练各是干什么用的，配一个生活化类比。⟩

⟨**收束**：以上整个 ⟨模型⟩ 的结构，现在来看它是如何被训练出来的。⟩

⟨对每个关键机制重复五步：⟩

1. ⟨**它要解决什么**⟩
2. ⟨**自问自答**：那现在问题来了，… 是怎么做到的？⟩
3. ⟨**类比**：1–2 句，保住机制的输入/输出/约束/代价⟩
4. ⟨**机制本体**：用论文自己的术语讲清怎么工作⟩
5. ⟨**为什么不是别的做法**：被否决的替代方案以及原因⟩

⟨对每个公式（无论是否有编号）重复五步：⟩

1. ⟨一句话说它算什么⟩
2. ⟨逐符号解释物理含义，不要只念字母⟩
3. ⟨代入具体数字算一遍⟩
4. ⟨训练时怎么用 / 推理时怎么用⟩
5. ⟨显式声明本篇的符号约定（尤其时间步方向）⟩

⟨公式一律写在数学定界符里：行内 `$…$`，独立成行 `$$…$$`；不要出现裸 `_{}` / `^{}`、
Unicode 上下标或组合附加符号。符号表统一用 Markdown 表格，且每个符号单元格都是 `$…$`：⟩

| 符号 | 物理含义 | 取值 / 量级 |
| --- | --- | --- |
| $⟨w_i⟩$ | ⟨这个量在系统里代表什么，不是它的名字⟩ | $⟨0.1⟩$ |
| $⟨N⟩$ | ⟨例如：总的测试次数⟩ | $⟨500⟩$ |

⟨需要带条件的定义式时，把那个 `$$` 块放在符号表上方或下方，不要塞进单元格里。⟩

## ⟨Data / Training recipe 的原标题（如有）⟩

⟨**为什么数据是核心**⟩

⟨**数据来源逐个讲**：名字（规范拼写）、规模、覆盖、采集方式、为什么选它。⟩

⟨**规模具象化**：至少把一个头号数字换算成能想象的量，并自己核算一遍。⟩

⟨**配比与平衡策略**：怎么混、按什么比例、避免了什么失败模式。⟩

⟨**格式统一**：维度补齐、缺失模态处理、单位归一。⟩

⟨**训练范式两阶段**：各优化什么、各用什么数据。⟩

---

## ⟨Experiments 的原标题⟩

⟨**设计总览**：论文第 X 节的评估围绕 N 个核心问题展开，一是…N是…⟩

⟨**考生**：受测的所有模型变体，带参数量与基座模型。⟩

⟨**对手**：每个基线一句话是什么 + 为什么选它（如果能超越它，就证明了什么）。⟩

⟨**指标**：逐个定义，并代入数字算一遍。写清成功判定标准。⟩

⟨对每个问题重复以下顺序：⟩

1. ⟨任务设置（做什么、在哪个平台上）⟩
2. ⟨条件与变化维度⟩
3. ⟨结果图位置：论文第 X 页的图 Y⟩
4. ⟨读数：谁赢、赢多少、给出数字⟩
5. ⟨原因解释：论文的解释 + 你对机制的解读⟩
6. ⟨takeaway 一句话结论⟩

⟨**消融 / 控制变量**：第一次出现时解释什么是消融，然后逐变体说清去掉了什么、分数怎么变。⟩

⟨**公平性与干扰因素**：论文自己承认的对照缺陷，说清为什么无法拆开。⟩

⟨**收束**：把这几个问题折回同一个被测主张。⟩

---

## ⟨Limitations / Discussion 的原标题⟩

⟨**承接句**：回扣前面某个设计，然后转折到局限。⟩

⟨逐条：**第 N 个局限是**… → 具体失败例子或类比 → 作者给出的改进方向。⟩

⟨**失败案例分析**：用具体场景讲清失败长什么样，再解释根因，再说明这是本文特有还是领域共性问题。⟩

⟨只写作者承认的局限，不写自己的批评。⟩

---

## ⟨Conclusion 的原标题⟩

⟨**回到核心问题**：总的来说，这篇论文主要就是在探索一个核心问题：⟨问题⟩？答案是 ⟨肯定/否定⟩。⟩

⟨**手段回顾**：通过构建 ⟨A⟩ 和设计 ⟨B⟩，让模型既能 ⟨能力1⟩，又能 ⟨能力2⟩。⟩

⟨**实验证据一句话**⟩

⟨**升华**：这篇论文告诉我们…／不仅是技术突破，更是一个理念范式。⟩

⟨（可选）**一句边界**：但距离真正的广泛应用还任重而道远。⟩
