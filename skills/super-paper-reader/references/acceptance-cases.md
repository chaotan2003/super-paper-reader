# 验收场景

结构校验验证技能格式，不证明内容质量。检查实际产物与行为，不以出现某些标题或措辞判定通过。

| 场景 | 验收重点 |
| --- | --- |
| 全文开头 | Abstract完整忠实译文；引言五步形成故事并归并三点有据贡献；无阅读路线 |
| 领域位置 | Related Work结合全文解释问题演进、必要概念、本文继承与改变；并行路线不编造直线继承，不声称完整领域史 |
| 方法总览 | “1. 方法概述”内融合问题建模、原主图与教学图，串起输入、原阶段与输出；符号与对象前后相同，不中途插入独立建模或重复总览 |
| 术语与符号 | 原名、缩写和记号在标题、图、正文、公式中一致；不自造模块别名，不改变量、上下标、帽子或依赖；普通中文叙述可读，不堆英文 |
| 方法实现 | “2. 具体实现”沿原算法连续展开，同阶段计算讲完再推进；输入来源、计算、原因、输出与去向连续；分支、循环和训练／部署边界准确，不凑固定模块数；不靠阶段标题、2.1等子节或单行标签组织正文 |
| 入门理解 | 每个新组件先有它要解决的具体困难，原术语随后命名；读者能用普通中文复述为什么需要下一阶段，而不只是背出步骤。普通词不堆英文，配置不打断主线；教学例子回到真实机制且不冒充实验 |
| 数学与监督 | 形式化术语和原公式不先于用途解释，保留正式表达并逐项读出运算；标签、参数更新及冻结范围清楚，不因追求形式完整而堆叠公式；预测到最终结果无缺步 |
| 实验完整回答 | 每组问题连接目的、对照原名和机制、设计、实际操作、对应图表结果及原因；不只报数字，也不机械分六栏 |
| 实验依据 | 原协议与比较条件充分，作者解释和额外分析分清；不编造缺失步骤、次数、种子、显著性或唯一原因 |
| 材料不完整 | 仅摘要／局部材料时明确范围，不生成不可得正文、图表或结论；明确要求不要外查时遵守 |
| 指定范围 | 简短问答未显式调用时不强制HTML；显式调用与局部修订都尊重用户范围，保留无关内容 |
| 阅读形式 | 主章节和章内编号正确，Method内部仅方法概述、具体实现两个小标题；段落过渡顺畅，无删标题造成的跳转；数学保留原字形；无正文加粗、可见来源定位、来源核对栏目、“补充”标题或Method折叠 |
| 网页验收 | 原图和公式可读、目录跳转、离线资源完整；桌面及约390px无全页横向溢出；关键图节点不能只在被截区域；底稿与成品一致，警告或未检查不算通过 |

## 代表材料回归

- π₀：用原组件名解释编码、attention交互、flow matching与积分，训练和推理各自闭合，参数量与频率按当前论文重核。
- Attention Is All You Need：沿真实章节解释Q/K/V、缩放、多头、掩码、位置编码和训练推理，再用WMT证据回答问题，不套机器人流程。
- SuperMimic：沿原图Collect data、Fit world model、Improve policy展开；policy、world model、critic、replay buffer及其原符号一致；分清8步记录action拟合与32步当前policy想象；保留异硬件比较、训练库覆盖及单种子接口等边界。

维护文档时核对链接、示例、入口与细则一致性，并运行skill-creator的结构校验。更新安装后核对文件完整性；渲染脚本修改或安装／迁移验收时运行 `node scripts/test-render.mjs`，验证独立目录、空格路径、内嵌资源、源稿保护及失败处理。开发试读可在工作区 `outputs/skill-validation/`，不属于运行依赖。
