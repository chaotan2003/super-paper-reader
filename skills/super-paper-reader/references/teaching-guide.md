# 讲解规范

## 统一原则

保留实际主章节顺序，章内沿理解与计算依赖推进。每节接住前面的困难或产物，说明下一步为何必要；不要把各节分别改写成互不相接的摘要。References 不逐条复述，必要附录内容接入相应机制。

先建立“为什么需要下一步”的因果链，再解释机制与数学。每次引入新组件，先让读者看到当前办法留下的困难，以及需要补上的能力，再给它的原文名称。只说“接着编码、然后预测、最后优化”是操作顺序，还不构成原因解释。解释深度以读者能走通推理为准，不用字数、模型数量或图表数量凑篇幅。

在核心理解关口，可用一个贯穿的教学例子展示当前输入、动作或中间量怎样变化，让下一环节的必要性可见，再回到原文真实对象。例子不得编造成论文实验，不能用类比代替精确机制，也不必每段都加例子。网络宽度、批量、硬件等配置放在机制讲完后，只保留影响理解的部分。

### 原术语与原符号

写作前在内部核对方法正文、主图、公式与算法，记录原名称／缩写、符号定义、输入输出和所属阶段。标题、图注、教学图与正文使用同一套名称和符号。原文自身不一致时说明差异，不擅自统一成第三种写法。

专有名词、组件名与阶段名直接沿用原文，首次在解释其用途后给出原名和必要中文释义，后面保持同一称呼。中文负责解释职责，不另造“动作生成模块”“经验仓库”等别名。动作、观测、状态、奖励等普通叙述可以用中文并对应原符号，不必每次写成英文；保留原术语不等于把整段写成中英混排。

数学保留原字母、大小写、上下标、帽子／横线、粗体、索引、时间含义、条件与函数参数。同一对象不换字母，同一字母不换含义；原文明确复用记号时解释上下文。尤其分清状态／观测、预测／记录、动作／噪声及各网络参数。排版可换行，不省略关键依赖或以简化式替换正式目标。

## Abstract

正文从实际版本摘要的完整忠实译文开始，保留各句主张、限定、对象、数字与作者语气，不加入解释、评价或其他版本内容。

## Introduction

用五个相接的编号部分讲研究故事：

1. 背景与领域问题：研究什么，为什么值得解决。
2. 现有方法的困难：怎样工作，解决了什么，为什么还不够。
3. 本文方法：如何回应困难，关键选择是什么。
4. 实验设计：准备检验哪些主张，采用哪些比较或场景。
5. 三点贡献：按引言证据归并为三点，不冒充作者原有三项清单。

解释转折与因果，使“已有基础 → 剩余困难 → 本文选择”连续。优先查看图1并利用其有效信息，图靠近解释；若不能说明方案，不把展示图当作方法框架。

## Related Work / Background

围绕理解本文所需的共同问题，结合引言、相关工作、实际方法与实验基线组织：已有办法怎样运行 → 解决什么 → 还卡在哪里 → 新思路怎样回应 → 本文继承和改变什么。以问题或关键选择为小节主语，代表工作提供证据，不堆模型名单，不重讲一遍引言。

每次转向须有问题上的联系。并行路线先交代共同目标与分歧，再解释本文的选择或组合；不为制造递进而编造直接继承、替代关系或一条年代直线。范围到能定位本文为止，不声称覆盖完整领域史，不默认追踪后续进展。

重要概念在需要处讲运作方式。例如解释 distillation，要说明教师提供什么、学生学什么、为何能合并能力及可能损失什么，不止给出缩写。结尾收束本文属于哪条路线、复用什么基础、改了哪个环节、仍未处理什么，自然接到方法。

## Overview

保留已有 Overview 章节，用原图建立系统和场景认识；Method 承接已有关系与符号，不再完整重复一遍总览。

## Method

保留原主编号，章名用 Method。成品内部只设“1. 方法概述”和“2. 具体实现”两个小标题。以下是写作时的组织指导，不是需要复制进成品的额外标题。两部分均用连续段落衔接，不设2.1等子节、阶段标题或独立加粗标签；不把删掉的标题原样降为单行问句。结构简化不压缩机制、公式及必要实现细节。

### 方法概述：问题建模与原图方案

先接住前文的困难，用普通语言说明最终使用时“给什么、做成什么”，以及训练为何困难，再引入表达这件事所需的最少原符号。开场建模明确输入、输出与任务目标即可；POMDP等形式化名称、累计回报及优化目标放到读者已理解其用途的位置，不因出现在原文前面就一次性堆到开头。区分任务输入与训练数据、直接预测与最终结果，不在读图中途插入独立建模。

随后结合论文真正的方法主图说明怎样求解。核验主图与图注，不默认图1就是框架。沿真实计算把输入交给原组件或阶段，说明关键中间量、输出及下一步为何需要它；分支说明汇合点，循环说明起点和返回位置。讲清“怎样实现刚才的目标”，不只按左右布局报告组件职责。

走到相应连接时，依据实际图例区分数据、监督与梯度，以及训练／推理、冻结／更新。图中省略的组件依正文说明接入位置，不给颜色或箭头编造含义。将 insight 落到关键选择或连接上；内部计算和详细公式留给后续展开。

### 方法概述的收束：教学示意图

原图说明后，在同一概述内画标为“教学示意”的输入—原处理阶段—输出图，串起刚才的方案。节点用原阶段／组件名，箭头尽可能标原变量或交接对象，名称与后续正文一致。不能用表格替代，也不能为凑固定模块数改造架构。

保持真实分支、循环与辅助监督，训练和部署分开。图过宽时简化主干、另画支路或分阶段呈现，并说明省略的依赖，不能在窄屏把关键节点截掉。原图不可得时依据可得正文绘制并标明限制，不假称核验过原图。

图后用简短过渡段接到具体实现，例如指出接下来要走通输入编码、监督来源及预测怎样变成结果。不另列问题清单或重开一套总览。

### 具体实现：沿计算链连续展开

以主图与算法的原阶段为内部骨架，同阶段计算讲完再推进，附录实现接在对应位置。阶段原名自然写入段落，例如“有了这些记录，便进入Fit world model……”，不再给阶段或内部步骤加标题。通过上一段的产物和剩余困难引出下一段，不能只删标题而留下突兀跳转；也不将网络、损失和超参数拆成不相连的内容或多次重新定义同一组件。

每个阶段自然串起：已有输入或结果能做什么 → 还不能做什么 → 所以需要当前机制 → 它怎样计算 → 得到什么并交给下一步。段落开头承接已有产物，结尾点出尚未解决的问题，不必排成重复字段。若有其他输入，先交代来源再汇合，不假称仅由上一节点生成。解释应让读者知道“为什么没有这一环就不够”，而不只记住各组件职责。

阶段内细节可按学习依赖组织，但不改变算法执行顺序。训练按采集、拟合、更新等真实顺序走通；部署另从实际可得输入走到输出，不在两条流程间跳转。循环解释初值、单步更新、复用量、终点及最终产物。

训练目标紧接被监督的计算：先讲样本、预测与标签从哪里来，再讲损失比较什么、更新谁、冻结谁。影响机制的配置就地解释，其余配置压缩。不能把真实标签作为推理输入，或把训练损失画成部署必经步骤；网络输出后的积分、搜索、动作换算等转换不得缺步。

## 公式与训练推理细节

引入公式前，读者应已知道这里要比较、预测或累计什么，以及为什么需要这个量；否则先补直觉和计算过程。随后保留原正式表达、名称与编号，逐项解释变量、运算、输出及下一用途；维度、取值范围和单位在影响理解时展开。公式负责精确表达已建立的机制，不负责首次引入一整套陌生概念。不能先列一批公式再跨节补解释。

损失要讲监督从何而来、比较什么、优化谁；迭代要讲起点、更新和终点；必要的推导或小算例标为教学内容，主计算链仍用原记号。作者未给设计理由时，不把自己的推测写成作者解释。

有独立 Data / Training / Inference 章节时沿原文展开，否则归入对应阶段。说明样本组织、采样、初始化、冻结与更新范围及使用流程，区分数据量、模型规模与预算。未知实现如实说明，不用惯例补齐。速度、频率与加速附对应设备、负载和基线，数值核对见证据规范。

## Experiments

开头先总说实验要回答哪些问题，再逐组以实际问题为编号标题。问题来自方法主张与已有实验，不固定数量，不添加作者未做的检验。同一问题可整合多图，不同问题不因共享一图而混讲；按整体效果、机制与适用范围等有据关系推进。

每组结合原文、图注、表格与必要附录协议，连续回答：

1. 目的：对应哪项主张，为什么要做，怎样的比较能回答问题。
2. 对照：原名是什么、怎样工作、关键差别在哪、为何选它；没有外部基线时说明自身变体或条件，不补造方法。
3. 设计：任务、数据或场景，改变与保持项，指标含义及优劣方向；关键硬件、数据量、预算和标准是否对齐。
4. 实施：实际怎样训练、使用哪个检查点、移除或冻结什么、怎样输入测试或施加扰动、怎样评测并汇总。只保留理解结果所需的原文预算、次数、种子和统计方法，不重讲整套 Method 或堆超参数。
5. 结果：在对应原图表附近解释关键轴、图例、子图或行列，用必要数值与趋势回答问题，不逐格报数。
6. 原因：优先说明作者解释，将其连到机制、实际差异及支持的消融。作者没解释时保留缺口；额外推断标为“讲解者分析”，交代依据与其他未排除解释。

六项是推理顺序，不强制六个小标题或问答卡。共享条件只说一次，后续说变化；原文缺项不为填模板而补造。区分趋势、单次结果、平均值和统计显著性，说明核心消融的混杂因素；性能改善不自动证明唯一因果，限定场景不自动支持普遍结论。外部资料可解释必要概念，不能替代当前论文的实验或原因。

## Discussion / Conclusion

总结有证据的收获、作者限制与适用边界。额外判断标为分析并给依据，不凭标题或局部结果夸大能力。
